TENOS Memory

TENOS에서 memory는 부가 기능이 아니라 기반 레이어다. 지금 구조도 마찬가지로 brain.db, MEMORY.md, daily memory, HEARTBEAT, LEARNINGS가 합쳐져서 실제 운영 맥락을 지탱하고 있다. TENOS는 이 기억 구조를 정확히 가져와야 flow, runtime, reporting이 흔들리지 않는다.

기억은 저장소가 아니라 운영 레이어
검색 + 주입 + 상태추적 + 저장이 한 세트
TENOS의 다른 모듈은 memory 위에 붙는다

1. 현재 기억 계층을 TENOS 기준으로 다시 본다

Layer 1
brain.db
장기 기억 저장소. 대화, 녹음, 문서, 요약, 회고가 쌓인다.
  • 검색 중심
  • 장기 보존
  • 원문 회수 가능
Layer 2
MEMORY.md
반드시 유지해야 하는 핵심 사실과 장기 의사결정 요약.
  • 큐레이션 기억
  • 장기적 사실
  • SSOT 성격
Layer 3
Daily Memory
최근 작업/대화/맥락을 이어주는 일일 로그.
  • 최근 맥락
  • 세션 연결
  • 단기 회고
Layer 4
HEARTBEAT / LEARNINGS
진행 중 상태와 실수/교훈을 추적하는 운영 메모리.
  • 진행상태
  • 작업 추적
  • 실수 방지

2. TENOS Memory가 실제로 책임지는 것

기능 1

검색

작업 시작 전에 관련 기억이 있는지 먼저 찾는다.

기능 2

주입

관련 기억만 카리나/실장/워커에게 컨텍스트로 넣는다.

기능 3

상태 추적

진행 중 작업을 HEARTBEAT 성격으로 유지한다.

기능 4

결과 저장

작업 결과, 교훈, 중요 의사결정을 다시 memory로 밀어넣는다.

3. 언제 검색하고 언제 저장하나

Step 1
작업 시작 전
비슷한 과거 작업이 있는지 먼저 검색.
  • brain.db
  • MEMORY
  • 관련 daily memory
Step 2
작업 분류 후
누구에게 무엇을 주입할지 결정.
  • 카리나용 요약
  • 실장용 맥락
  • 워커용 최소 컨텍스트
Step 3
작업 중
진행 중 상태는 HEARTBEAT 성격으로 유지.
  • 누가 맡았는지
  • 어디까지 왔는지
  • 막힌 지점
Step 4
작업 완료 후
결과를 저장소에 되밀어 넣는다.
  • brain.db 기록
  • daily memory 반영
  • 필요시 MEMORY 갱신
Step 5
반복 패턴 발견
실수/패턴은 LEARNINGS나 룰 후보로 승격.
  • 교훈 축적
  • 재발 방지
  • 시스템 개선

4. 어떤 memory를 누구에게 주입하나

대상주입되는 memory왜 그렇게 하나
카리나MEMORY, 관련 brain.db 검색결과, 최근 daily memory, HEARTBEAT 핵심판단과 분배를 해야 하므로 큰 그림이 필요함
실장관련 업무 맥락, 과거 사례, 현재 진행상태, 목표/KPI기획/지시/검수에 필요한 실무 수준 컨텍스트가 필요함
팀원 worker해당 작업에 필요한 최소 맥락, 관련 예시, 명확한 출력조건불필요한 컨텍스트 오염을 줄이고 실행에 집중시켜야 함

5. TENOS Memory에서 주의할 점

주의 1

많이 넣는 게 능사가 아님

관련 없는 기억을 너무 많이 주입하면 오히려 판단이 흐려진다.

주의 2

장기 기억과 상태 기억을 섞지 말 것

MEMORY와 HEARTBEAT는 역할이 다르다. 하나는 사실, 하나는 현재 상태다.

주의 3

결과 저장이 빠지면 시스템이 안 자란다

검색만 하고 저장 안 하면 TENOS는 계속 같은 실수를 반복한다.

6. TENOS Memory의 V1 범위

V1에서 꼭 필요한 것:
1) brain.db 검색
2) MEMORY / daily memory / HEARTBEAT 읽기 규칙
3) 작업 완료 후 결과 저장 규칙
4) 진행 중 상태 업데이트 규칙
이 4개만 먼저 제대로 구현하면 된다.
