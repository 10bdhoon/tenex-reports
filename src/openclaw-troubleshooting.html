🔄 문제 1: 토큰 전환했는데 이전 계정을 계속 씀

원인

OpenClaw는 각 에이전트마다 auth-profiles.json을 가지고 있고, 여기에 lastGood (마지막 성공 계정)을 캐시합니다.

openclaw.json의 auth.order만 바꾸면, lastGood에 이전 계정이 남아있어서 계속 이전 계정을 시도합니다.

해결: 원스텝 토큰 전환 스크립트

터미널에서 실행: bash ~/.openclaw/workspace/scripts/switch-token.sh tenex-kr
스크립트가 자동으로: openclaw.json order + 5개 에이전트 auth-profiles.json lastGood 전부 변경
Claude Code CLI도 변경: Claude Code 열고 /login 입력 → 해당 계정으로 로그인
openclaw gateway restart

💥 문제 2: openclaw.json 설정이 날아감

원인

  • openclaw configure (wizard) 실행 → 기존 설정을 최소값으로 덮어씀
  • 절대 금지 이미 설정된 상태에서 openclaw configure 실행하지 말 것

복구 방법

백업 확인: ls ~/.openclaw/config-backups/
최신 백업 복원: cp ~/.openclaw/config-backups/openclaw.json.YYYY-MM-DD ~/.openclaw/openclaw.json
openclaw doctor && openclaw gateway restart

백업 없으면?

brain.db에서 토큰 복구 가능:

sqlite3 ~/.openclaw/workspace/brain/brain.db "SELECT content FROM memories WHERE content LIKE '%xoxb%' LIMIT 10"
sqlite3 ~/.openclaw/workspace/brain/brain.db "SELECT content FROM memories WHERE content LIKE '%xapp-%' LIMIT 10"

슬랙 봇토큰(xoxb-), 앱토큰(xapp-) 찾아서 수동 재작성.

🔒 문제 3: exec 명령이 승인 타임아웃

원인

openclaw.json에서 tools.elevated 설정이 날아가면 exec 승인이 안 잡힘

해결

openclaw.json에 추가:

{
  "tools": {
    "elevated": {
      "enabled": true,
      "allowFrom": {
        "telegram": ["5901218950"],
        "slack": ["U06C2NEGQ68"]
      }
    }
  }
}
