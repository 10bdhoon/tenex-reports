TENOS Roadmap

TENOS Roadmap은 “무엇을 언제 구현할지”를 정하는 문서다. 핵심은 욕심을 줄이고, V1에서 테넥스 AI 조직을 굴리는 데 꼭 필요한 것만 먼저 구현하는 것이다. 즉 OpenClaw 전체 복제가 아니라, TENOS가 실제로 돌아갈 최소 커널부터 올리는 순서표다.

원칙: 범용 플랫폼 금지
원칙: V1은 최소 커널
원칙: 파일럿으로 검증 후 확장

1. 전체 로드맵 개요

Phase 1
V1
최소 실행기
  • 메시지 입력 수신
  • 카리나/실장 라우팅
  • worker spawn
  • memory 검색/저장
  • 상태 추적
  • 보고 루프
  • 기본 스케줄러
Phase 2
V2
운영 안정화
  • 권한/승인 체계 고도화
  • 실패 복구 / retry 정책 강화
  • 파일럿 도메인 확장
  • 상태 시각화 뷰 추가
Phase 3
V3
확장 / 최적화
  • Console 고도화
  • 자율 제안 / 패턴 승격
  • 도메인별 세부 엔진 확장
  • 운영 자동화 강화

2. V1에서 반드시 들어가야 할 것

V1 필수

Input Router

Telegram, Slack, cron event 입력을 받는 관문.

V1 필수

Lead Orchestration

카리나와 실장에게 어떤 요청을 보낼지 결정.

V1 필수

Worker Spawn

필요시만 실행 worker를 띄우는 최소 런타임.

V1 필수

Memory Layer

brain.db 검색, MEMORY/HEARTBEAT 읽기, 결과 저장.

V1 필수

Task State

누가 맡았고 어디까지 왔는지 상태 추적.

V1 필수

Report Loop

실장 → 카리나 → 태훈 보고 체계.

V1 필수

Basic Scheduler

정시 실행, 리마인더, 자동 이벤트 처리.

3. V1에서 일부러 안 하는 것

보류

범용 에이전트 플랫폼

OpenClaw 같은 범용 제품을 새로 만드는 건 안 한다.

보류

고급 웹 콘솔

V1에서는 예쁜 관리 UI보다 작동이 먼저다.

보류

자동 스킬 생성

학습 자동 승격은 V3 이후에 보는 게 맞다.

보류

멀티모델 최적화 엔진

처음부터 모델 스위칭 최적화에 집착하지 않는다.

4. 어떤 도메인으로 먼저 파일럿할까

도메인장점추천도
마케팅반복도 높고, 분석/리포트/소재 보조처럼 구조화하기 쉬움높음
CRM고객 흐름 설계와 자동화 검증에 좋음높음
CS실무 임팩트는 크지만 승인/리스크 관리가 더 중요함중간
개발 운영기술적으로는 좋지만 실패시 리스크 체감이 큼중간
