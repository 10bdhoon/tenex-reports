TENOS 마이그레이션 자산맵

구현 들어가기 전에 필요한 건 문서 대청소가 아니라, OpenClaw 안의 기존 자산을 무엇을 가져가고, 무엇을 참고만 하고, 무엇을 버릴지 분류하는 것이다. 이 페이지는 TENOS V1 구현 전에 필요한 자산 정리 지도다.

목표: 대청소 금지, 분류 먼저
핵심: 프롬프트가 아니라 운영체계를 옮긴다
기준: TENOS V1에 필요한 것만 남긴다

1. 먼저 3개 버킷으로 나눈다

가져갈 것

Keep

  • 조직 구조 관련 문서
  • 카리나 / 실장 / 팀원 역할 정의
  • 보고 경로와 승인 규칙
  • MEMORY / HEARTBEAT 운영 방식
  • brain.db 사용 구조
  • 자동화 목록, 크론 목록
  • 채널 라우팅 규칙
참고만 할 것

Reference

  • OpenClaw 전용 설정법
  • gateway-specific 운영법
  • token 전환 트릭
  • 특정 툴 사용법
  • OpenClaw 내부 명령/옵션 의존 자료
버려도 되는 것

Drop

  • OpenClaw 종속 임시 시행착오 문서
  • 지금 구조와 안 맞는 예전 프롬프트 찌꺼기
  • 중복 설명 파일
  • 현재 운영과 무관한 구버전 노트

2. TENOS로 옮길 핵심 자산

이건 구현 전에 반드시 목록화돼 있어야 한다.

자산왜 필요한가TENOS에서의 위치
카리나 역할 정의메인 허브의 판단 범위를 고정해야 함TENOS Core / Flow
실장별 역할 정의실장과 팀원 역할 경계가 무너지면 구조가 깨짐TENOS Core / Runtime
보고 경로실장 → 카리나 → 태훈 루프를 강제해야 함TENOS Flow / Policy
승인 규칙민감 작업과 사람 승인 게이트를 시스템화해야 함TENOS Policy
memory 구조기억 주입과 저장이 시스템 핵심임TENOS Memory
brain.db 활용 방식장기 기억 검색/기록의 중심 저장소TENOS Memory
HEARTBEAT 구조진행 중 작업 상태 추적의 기준TENOS Memory / Flow
자동화 / 크론 목록무엇을 scheduler가 돌려야 하는지 알아야 함TENOS Runtime / Scheduler
채널 라우팅 규칙텔레그램/슬랙 입력이 어디로 가는지 기준 필요TENOS Router

3. OpenClaw 기능 중 TENOS V1에 필요한 것만 추린다

필수

메시지 받기

텔레그램, 슬랙, 자동 이벤트 입력 수신.

필수

카리나 / 실장 라우팅

누가 처리할지 결정하는 분배 로직.

필수

worker 실행

필요시 spawn해서 실행하고 끝나면 종료.

필수

memory 검색 / 저장

brain.db, MEMORY, HEARTBEAT 연동.

필수

상태 추적

작업이 누구 손에 있고 어디까지 왔는지 추적.

필수

보고 루프

카리나 경유 최종 보고, 사람 승인 포함.

필수

스케줄 실행

정시 자동화와 크론 이벤트 처리.

보류

범용 플랫폼 기능

처음부터 OpenClaw 전기능 복제는 안 한다.

4. 제일 중요한 주의점

프롬프트를 옮기는 게 아니라 운영체계를 옮기는 거다.
md 파일 몇 개 복붙한다고 TENOS가 되는 게 아니다. 핵심은 역할, 흐름, 기억, 보고, 승인 이 다섯 개를 시스템 레벨로 옮기는 것이다.
