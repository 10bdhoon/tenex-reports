TENOS Policy

TENOS Policy는 “어떤 작업은 바로 가고, 어떤 작업은 멈추며, 누가 승인하고, 무엇이 위험한지”를 정의하는 문서다. Event Flow가 작동 순서라면, Policy는 그 흐름 중간에 들어가는 안전장치다.

원칙: 위험 작업은 중간에서 멈춘다
원칙: 카리나가 최종 허브다
원칙: 사람 승인 필요한 영역은 자동화하지 않는다

1. TENOS Policy가 답해야 하는 질문

질문 1

누가 승인하나?

태훈, 카리나, 실장 중 어떤 레벨에서 결정을 끊는지.

질문 2

어디서 멈추나?

광고, 배포, 고객대면, 민감 변경은 어느 단계에서 hold 되는지.

질문 3

무엇이 금지되나?

V1에서 AI가 독단 실행하면 안 되는 작업들을 명확히 구분.

2. 승인 레벨

레벨주체역할
Level 1태훈광고 ON/OFF, 예산, 운영상 리스크 큰 변경, 배포/민감한 외부 액션 최종 승인
Level 2카리나실장 결과 검수, 우선순위 조정, 사용자에게 전달할 최종 언어와 방향 조정
Level 3실장도메인 내부 기획/지시/검수. worker 산출물 품질 확인

3. 위험 작업 분류

분류예시정책
광고 변경광고 ON/OFF, 예산 변경, 캠페인 상태 변경태훈 직접 승인 필수
고객 대면CS 답변, 공식 댓글/메시지, 외부 발신초기엔 사람 승인 후 발행
배포 / 설정서버/설정 변경, 운영 리스크 있는 배포카리나 검수 + 필요시 태훈 승인
내부 분석리포트, 요약, 초안, 리서치바로 생성 가능, 보고 후 저장

4. 금지 / 제한 원칙

금지

AI 독단 외부 실행

광고 상태 변경, 민감한 고객대면 발송, 위험한 설정 변경을 AI가 혼자 결정하면 안 된다.

금지

실장 bypass

worker가 사용자에게 직접 최종 보고하거나 독단적으로 루프를 닫으면 안 된다.

제한

고객 대면 자동화

초기엔 승인 기반, 승인율이 충분히 높아진 뒤 단계적 자율화.

제한

배포 / 보안 작업

실행 전에 위험도 판단과 rollback 가능성 검토 필요.

5. 흔들리면 안 되는 운영 원칙

핵심 원칙 4개:
1) 카리나는 모든 실장의 상위 허브다.
2) 실장은 판단하고 worker는 실행한다.
3) 민감 작업은 중간에서 멈추고 사람 승인 후 진행한다.
4) 결과 저장까지가 완료다.
