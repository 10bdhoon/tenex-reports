정품등록 추천 시스템 — 이게 어떻게 돌아가는가

개발 넘기기 전에 "구조"부터 완벽히 이해하기 · 2026-06-18
정품등록을 하면 내 카드의 시리얼코드가 곧 친구에게 주는 할인코드가 된다. 친구가 그 코드로 사면 → 친구는 10% 할인, 나는 5천원 적립. 모든 정산은 별도 시스템 없이 카페24 적립금으로 끝난다.
🏬 큰 그림 — 카페24는 안 바뀐다
카페24를 뜯어고치는 게 아니라, 그 "옆에" 작은 프로그램 하나가 새로 생긴다.
🧾
카페24 = 백화점 계산대. 그대로 둔다. 할인·적립 실행은 여기가 함.
🗂️
새로 만드는 프로그램 = 계산대 옆 "멤버십 관리실". 누구 시리얼이 누구 건지 장부를 들고 있다가, 결제가 일어나면 주인을 찾아 적립을 지시한다.
📝
정품등록 페이지 = 이미 있음. 장부에 "이 시리얼은 나" 하고 이름 올리는 입구.
이미 있음
📝 정품등록 페이지
"내 시리얼 KM-7F3Q는 나" → 장부에 주인 등록
↓ 주인 정보 저장
★ 새로 만드는 것 (Vercel 서버 + DB)
🗂️ 멤버십 관리실 (시스템의 두뇌)
시리얼 ↔ 주인 장부 보관 · 결제 감지 → 주인 조회 → 적립 지시
↑ "○○코드로 결제됨"(webhook)  /  ↓ "주인에게 5천 적립"(API)
거의 그대로
🧾 카페24 쇼핑몰
시리얼 입력 → 10% 자동할인(기본기능) · 적립금 실행
🔄 실제로 일어나는 일 (4단계)
손님이 친구 카드의 시리얼코드를 들고 카페24에서 결제 → 계산대(카페24)가 알아서 10% 깎음
카페24가 우리 관리실에 쪽지를 보냄: "이 코드로 결제됐어" (webhook)
관리실(새 프로그램)이 장부를 뒤짐 → "이 코드 주인 = 박씨"
관리실이 카페24에 지시: "박씨 통장에 5천 적립" → 카페24가 실행

⚠️ 어뷰징 가드 — 자기추천 차단: 시리얼 주인 = 구매자가 동일인(폰번호 or 카페24 계정 일치)이면 적립 미지급. 자기 코드로 자기가 사서 할인+적립 동시에 먹는 것 차단.
🧩 뭐가 바뀌고 / 뭐가 새로 생기나
🔒 거의 안 바뀜 — 카페24
  • 쇼핑몰 화면·구조 그대로
  • 설정 2개만: ①시리얼을 쿠폰으로 등록 ②결제완료 webhook 켜기
  • 할인·적립 실행은 카페24 기본기능
✨ 새로 생김 — 관리실 프로그램
  • 작은 서버 + DB 1개 (Vercel, tenex-dashboard들처럼)
  • 시리얼↔주인 장부 + 자동 적립 두뇌
  • 시리얼 발급/위조검증(난수+체크문자)
👤 대표(나)가 보고 활용하는 것
새로 생기는 관리자 화면에서:
  • 누가 누구를 추천했나 (추천 네트워크)
  • 적립금 얼마 나갔나 (비용 추적)
  • 시리얼 전체 명단 / 정품등록 현황
고객 입장에선 달라지는 게 없다 — 기존 카페24 쇼핑몰 + 정품등록 페이지를 그대로 쓴다.
📋 등록 폼 보완 2가지 (확정)
기존 정품등록 폼이 곧 "장부". 추천 붙이려면 딱 2개만 보완하면 됨.
① 시리얼코드 입력란 추가
  • 지금 폼은 주문번호만 받음 → 시리얼 안 받음
  • 시리얼=추천코드라 등록 때 받아야 "주인=누구" 장부 생성
  • 체크문자로 가짜 코드 즉시 거름
② 카페24 가입 연결 — B안
  • 등록은 지금처럼 폰번호로 자유롭게
  • 적립금 생기면 → "5천원 받으려면 공식몰 가입" 유도
  • 같은 폰번호로 가입 시 자동 매칭 · 적립금이 미끼
B안 선택 이유: 적립금은 카페24 계정에만 줄 수 있는데 네이버·쿠팡 구매자는 미회원일 수 있음. 등록 문턱 안 높이고, 오히려 적립금이 사람들을 공식몰로 끌어오는 미끼가 되게 함.
🚀 다음 단계
개발 한 흐름: 시리얼 생성 → 회원매칭 → 쿠폰할인 등록(노코드) → 시리얼 주인 자동적립(개발 본체)
개발 담당(개실장)이 착수하며 카페24에 확인할 3가지: ①대량 쿠폰코드(3,000개) 등록 방식 ②결제 webhook이 입력 시리얼값을 주는지 ③기존 등록폼의 회원연동 현황.
