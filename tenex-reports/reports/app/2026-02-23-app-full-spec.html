3. 홈 화면 (index.tsx)

3.1 핵심 기능

① 오늘의 상태 체크 팝업

  • 앱 진입 시 pain_score 미입력이면 바텀시트 모달 자동 표시
  • 1~10점 선택 (1=많이 아픔, 10=괜찮음)
  • 점수 제출 → savePainScore() → +10P 적립 (status_check)
  • 점수 범위별 루틴 분기: ≤3 (회복 집중), 4~6 (회복+교정), ≥7 (교정+운동)

② 맞춤 루틴 시스템

점수루틴 구성설명
1~3점WS-200 찜질 → ES-808 자극 → 가벼운 스트레칭 영상회복 집중
4~6점WS-200 찜질(선택) → CS-25 교정 → 목 스트레칭 영상회복+교정
7~10점CS-25 교정 → 1분 운동 영상 → 마무리 스트레칭 영상교정+운동
  • 제품 미보유 시 "구매하기" 버튼 표시 (자사몰 WebBrowser)
  • 보유 시 "지금하기" → ProductGuideModal로 사용 가이드 제공
  • 모든 루틴 완료 시 +30P (routine_complete)

③ 오늘의 1분 운동 영상

  • 유튜브 숏츠 5개 중 랜덤 선택 (react-native-youtube-iframe)
  • 영상 끝까지 시청 시 markVideoWatched() → +100P (exercise_complete)
  • 체크인 자동 처리 + 스트릭 업데이트

④ 챌린지 진행률 카드

  • 온보딩에서 선택한 14일/21일 챌린지 기반
  • 연속 일수, 남은 일수, 달성률(%) 표시
  • 프로그레스 바 시각화

⑤ 크로스셀 추천 제품

  • Supabase products 테이블에서 보유 제품 제외 → display_order 순 첫 번째
  • 모든 제품 보유 시 표시 안 함
  • 클릭 → expo-web-browser로 자사몰 오픈

3.2 상태 관리

  • useAuthStore — user, isAuthenticated
  • usePointStore — points, earnPoints, checkDailyLogin, checkStreakRewards
  • useOnboardingStore — challengeType, products (보유 제품)

4. 회복 점수 화면 (recovery.tsx)

4.1 주요 섹션 (상→하 스크롤)

① 오늘의 상태 체크

  • 1~10점 선택 UI (홈과 동일한 슬라이더)
  • 체크 완료 후 "탭하여 수정" 기능 (isEditingScore)
  • 수정 시 포인트 추가 적립 없음 (중복 방지)

② 나의 회복 여정

  • 총 운동 일수 (journeyData.totalDays)
  • 연속 참여 일수 (weeklyScores 기반 계산)
  • 누적 포인트 (formatPoints)

③ 내 통증 부위

  • 온보딩에서 선택한 통증 부위 뱃지 표시
  • 탭하여 수정 가능 (painAreaModal)
  • 부위별 이모지: 목/어깨🦴, 손목✋, 허리🔙, 무릎🦵, 발목🦶, 기타📌

④ 통증 추이 그래프

  • 최근 7일 바 차트 (점수별 색상: 1-3 빨강, 4-6 노랑, 7-10 초록)
  • 지난주 대비 변화량 뱃지 (↑개선 / ↓악화)
  • 첫 주 vs 최근 7일 평균 비교 카드

⑤ 오늘의 회복 팁

  • 통증 점수 기반 개인화 팁 (3개)
  • 통증 부위 기반 추가 팁 (목/어깨, 허리, 손목 등)
  • 제품 미보유 시 구매 유도 팁

⑥ 내 제품 관리

  • 보유 제품: 가이드 모달 → 사용 인증 (사진+메모 필수)
  • 미보유 제품: "보유중" 토글 + "구매" 버튼
  • 인증 완료 시 커뮤니티 '챌린지 인증' 카테고리에 자동 게시 (+50P)

4.2 제품 사용 인증 플로우

제품 카드 "가이드" 탭 → ProductGuideModal 표시 (사용법, 권장시간, 주의사항) → "사용 완료하기 +50P" 클릭 → 인증 모달 (사진 촬영/갤러리 + 한줄 메모) → addProductUsed() + 커뮤니티 자동 게시 → +50P 적립 (product_use)

5. 커뮤니티 화면 (community.tsx)

5.1 구조

  • 헤더: "커뮤니티" + 아이콘
  • 탭 필터: 전체 | 회복 후기 | 챌린지 | Q&A
  • 공지사항 섹션: notices 테이블에서 최신 3개 (빨간 왼쪽 보더)
  • 베스트 회복 후기: is_best=true인 게시물 (골드 보더)
  • 피드: FlatList + pull-to-refresh
  • FAB: 우하단 + 버튼 → /community/create

5.2 게시물 카드 (Post)

  • 작성자 아바타(이니셜) + 닉네임 + 카테고리 뱃지 + 시간
  • 본문 (최대 4줄) + 미디어 (이미지/비디오)
  • 좋아요/댓글 수 + 좋아요/댓글/공유 액션
  • 내 게시물: ⋯ 메뉴 → 수정/삭제

5.3 게시물 상세 ([id].tsx)

  • 전체 본문 + 미디어 캐러셀 (다중 이미지/비디오, 페이지 인디케이터)
  • 좋아요 토글 (optimistic update + DB 트리거 카운트)
  • 댓글 목록 + 댓글 입력 (비로그인: 익명 안내)
  • KeyboardAvoidingView로 입력 UX 최적화

5.4 글쓰기 (create.tsx)

  • 카테고리 선택: 챌린지 인증 | Q&A | 회복 후기
  • 미디어: 사진 최대 5장, 동영상 최대 1개 (60초)
  • 갤러리/카메라/비디오 촬영 버튼
  • 게시 시 +30P (post_create) 적립
  • 비로그인 시 익명 글 작성 (미디어 첨부 불가)

15. 주요 설계 패턴

  • 오프라인 퍼스트 모든 데이터 작업에 AsyncStorage 폴백 → Supabase 장애 시에도 앱 정상 작동
  • Optimistic Update 좋아요/댓글 수를 즉시 UI 반영 후 서버 동기화 (communityStore)
  • DB 트리거 likes_count, comments_count는 DB 트리거로 자동 동기화 (클라이언트 집계 불필요)
  • 세션 복구 Supabase 세션 만료 시 자동 refreshSession() 시도 → 실패해도 로컬 저장
  • 중앙 상수 제품 정보/가이드/이미지를 constants/products.ts에 통합 → 중복 제거
  • 통합 훅 useProductGuideModal로 가이드 모달 상태를 하나로 관리 → 홈/회복 화면 공유
  • Fallback Supabase 제품 조회 실패 시 하드코딩된 fallbackProducts 사용
