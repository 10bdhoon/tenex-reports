2. OAuth 2.0 인증 흐름

[1] 최초 인증 client_id + client_secret → Authorization Code → POST /api/v2/oauth/token → access_token (2시간) + refresh_token (2주) [2] 토큰 갱신 POST /api/v2/oauth/token { "grant_type": "refresh_token", "refresh_token": "{현재_refresh_token}" } → 새 access_token + 새 refresh_token [3] ⚠️ 갱신 시 즉시 memory/api-credentials.md 업데이트!

토큰 수명

토큰수명주의사항
access_token2시간만료 시 자동 갱신 필요
refresh_token2주갱신 시 이전 토큰 즉시 무효

3. 토큰 갱신 절차 (코드 예시)

// Node.js 토큰 갱신 예시 const response = await fetch( 'https://bdhoon10.cafe24api.com/api/v2/oauth/token', { method: 'POST', headers: { 'Content-Type': 'application/x-www-form-urlencoded', 'Authorization': 'Basic ' + Buffer.from(CLIENT_ID + ':' + CLIENT_SECRET).toString('base64') }, body: 'grant_type=refresh_token&refresh_token=' + REFRESH_TOKEN } ); const { access_token, refresh_token } = await response.json(); // → 즉시 memory/api-credentials.md 및 Render 환경변수 업데이트

4. 주문 조회 API

Scope: mall.read_order

GET /api/v2/admin/orders?shop_no=5&start_date=2026-02-21&end_date=2026-02-21 Headers: Authorization: Bearer {access_token} Content-Type: application/json X-Cafe24-Api-Version: 2024-06-01 Response: { "orders": [ { "order_id": "...", "order_amount": "...", ... } ] }

⚠️ shop_no 주의: shop_no를 지정하지 않으면 shop_no=1(봉삭스) 주문만 조회됨. 반드시 shop_no=5 또는 shop_no=6 지정 필요.

5. 주의사항 체크리스트

  • ✅ 토큰 갱신 후 즉시 memory/api-credentials.md 업데이트
  • ✅ Render 환경변수의 CAFE24_REFRESH_TOKEN도 동기화
  • ✅ 주문 조회 시 반드시 shop_no=5 또는 shop_no=6 명시
  • ✅ API 호출 시 X-Cafe24-Api-Version 헤더 필수
  • ⚠️ refresh_token은 1회용 — 갱신하면 이전 토큰 즉시 만료
  • ⚠️ 2주 내에 갱신하지 않으면 재인증 필요 (Authorization Code부터 다시)
