1. Executive Summary

테넥스의 모든 비즈니스 지식 — 미팅 녹음, 강의 콘텐츠, 고객 VOC, 제품 정보, 마케팅 인사이트 — 을 벡터 임베딩하여 AI가 실시간으로 참조할 수 있는 지식 순환 시스템.

최종 목표: 팀원이 슬랙에서 질문하면, 태훈의 의사결정과 지식 기반으로 AI가 자동 답변. 카리나(텔레그램 에이전트)도 동일한 지식 DB를 참조하여 대화 품질 향상.

핵심 차별점: 단순 검색이 아닌 "지식 → 활용 → 승인 → 재순환" 자기강화 루프. 시간이 지날수록 시스템이 더 똑똑해짐.

검색 파이프라인 상세

질문 입력 ↓ ① Query Expansion (Claude) "CS-25 반품 많아?" → ["CS-25 반품", "CS-25 클레임", "교정기 반품 사유"] ↓ ② Hybrid Search Vector cosine similarity × 0.6 + Full-Text Search × 0.4 + source_type tier_boost (T1: ×1.2 / T2: ×1.0 / T3: ×0.8) ↓ ③ Reranking (Gemini Flash) 상위 20개 → 질문과 관련성 재평가 → 최종 5개 선별 ↓ ④ 답변 생성 (Claude) 선별된 5개 chunk + 원본 질문 → 근거 기반 답변

4. DB 스키마 설계

knowledge_contents — 원본 콘텐츠

CREATE TABLE knowledge_contents ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), title TEXT NOT NULL, raw_content TEXT NOT NULL, source_type TEXT NOT NULL, -- lecture | meeting | voc | product | marketing | internal | content source_ref TEXT, -- 원본 URL, 파일명, Plaud ID 등 ai_summary TEXT, -- Claude/Gemini 자동 요약 importance_score SMALLINT DEFAULT 5, -- 1-10 중요도 (태훈 수동 or AI 판단) key_topics TEXT[], -- 주요 토픽 태그 embedding_status TEXT DEFAULT 'pending', -- pending | processing | done | error created_at TIMESTAMPTZ DEFAULT now() );

knowledge_chunks — 임베딩된 청크

CREATE TABLE knowledge_chunks ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), content_id UUID REFERENCES knowledge_contents(id) ON DELETE CASCADE, chunk_text TEXT NOT NULL, chunk_index INT NOT NULL, embedding vector(768), -- Gemini gemini-embedding-001 source_type TEXT NOT NULL, priority SMALLINT DEFAULT 5, -- 상위 콘텐츠 importance 상속 token_count INT, created_at TIMESTAMPTZ DEFAULT now() ); -- 검색 성능을 위한 HNSW 인덱스 CREATE INDEX idx_chunks_embedding ON knowledge_chunks USING hnsw (embedding vector_cosine_ops) WITH (m = 16, ef_construction = 64); -- Full-Text Search 인덱스 (한국어) CREATE INDEX idx_chunks_fts ON knowledge_chunks USING gin (to_tsvector('simple', chunk_text));

knowledge_usage_logs — 사용 추적

CREATE TABLE knowledge_usage_logs ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), consumer_type TEXT NOT NULL, -- slackbot | karina | report | manual query TEXT, chunks_used UUID[], -- 참조된 chunk IDs model TEXT, -- claude-opus | claude-sonnet | gemini-flash input_tokens INT, output_tokens INT, latency_ms INT, feedback TEXT, -- good | bad | null (사용자 피드백) created_at TIMESTAMPTZ DEFAULT now() );

5. 파이프라인 4계층

Layer 0 — 데이터 수집 & 임베딩

소스처리 흐름자동화
Plaud 녹음녹음 → Gemini 전사 → 청킹(700자) → Gemini 임베딩 → knowledge_chunks수동 트리거
유튜브 자막YouTube API 자막 추출 → 청킹 → 임베딩새 영상 감지 시 자동
Cafe24 VOCVOC API → 문의/리뷰/반품 수집 → 청킹 → 임베딩일 1회 배치
제품 정보constants/products.ts 파싱 → 제품별 청킹 → 임베딩코드 변경 시
Notion 문서수동 복사 or API → 청킹 → 임베딩수동

Layer 1 — 검색 엔진

  • Query Expansion: 사용자 질문 → Claude가 관련 검색어 3개 추가 생성 (동의어, 관련 개념)
  • Hybrid Search: vector cosine similarity (가중치 0.6) + PostgreSQL FTS (가중치 0.4) + source_type tier 부스트
  • Reranking: Gemini Flash가 상위 20개 결과를 질문 맥락에서 재평가 → 최종 5개 선별
  • 캐싱: 동일/유사 질문은 이전 검색 결과 재사용 (usage_logs 기반)

Layer 2 — 활용 (Consumer)

소비자시나리오모델
🤖 슬랙봇팀원: "CS-25 사이즈 교환 기준이 뭐야?" → RAG 검색 → 근거 기반 답변Sonnet
💬 카리나태훈 텔레그램 대화 중 "지난주 미팅에서 뭐라고 했지?" → 미팅 녹음 검색Opus
📊 일일 리포트매출 하락 감지 → 과거 유사 패턴 검색 → 인사이트 자동 추가Sonnet
🎯 의사결정 지원"이 제품 단종할까?" → 매출/VOC/마진 데이터 종합 검색 → Opus 분석Opus

Layer 3 — 순환 (Knowledge Loop)

시스템이 생성한 지식이 다시 지식 DB로 순환되는 자기강화 루프:

  • 승인된 답변 → 재임베딩: 슬랙봇 답변 중 "좋아요" 피드백 받은 것 → qa_answer source_type으로 재임베딩
  • 일일 리포트 인사이트 → 재임베딩: AI가 발견한 패턴/인사이트를 지식으로 축적
  • 의사결정 기록 → 재임베딩: 태훈의 주요 의사결정과 근거를 저장
  • ⚠️ 관리자 승인 게이트: 모든 순환은 태훈 텔레그램 승인 후에만 실행 → 잘못된 지식 유입 방지
🔄 지식 순환 루프 슬랙봇 답변 ─── 👍 좋아요 ──→ 태훈 승인? ──→ ✅ 재임베딩 (qa_answer) │ 일일 리포트 인사이트 ──────────→ 태훈 승인? ──→ ✅ 재임베딩 (insight) │ 의사결정 기록 ─────────────→ 태훈 승인? ──→ ✅ 재임베딩 (decision) │ ❌ 거절 → 폐기
